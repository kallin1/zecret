## 1. 기획 개요 및 서론

### 기획 의도

민간 건축사업자가 신축 건물을 계획할 때는 인접한 국가유산·군사시설 등 공개제한구역의
높이 기준을 위반하지 않는지 사전에 확인해야 한다. 문제는 군사시설 등 공개제한구역의
정확한 고도제한 수치가 안보상 이유로 **공개되지 않는다**는 점이다 — "안보상 비공개"와
"민간의 사전 확인 필요성"이 정면으로 충돌한다.

ZeCret은 이 충돌을 "높이제한 기준값(Z)을 복호화하지 않고도 비교 연산 자체를 수행하는"
동형암호(CKKS)로 해소한다. 서비스는 비밀키를 전혀 보유하지 않고, 암호문(Z) − 평문(계획
높이)의 동형 뺄셈까지만 수행하며, 최종 부호 판정(초과 여부)은 비밀키를 가진 관리기관
HSM 역할의 별도 검증 API에서만 이뤄진다.

### 서비스 소개

- **이름**: ZeCret (Z + Secret)
- **한 줄 정의**: 민간 사업자의 신축 계획이 인접 공개제한구역의 암호화된 높이(Z)값
  기준을 위반하는지만 판정해 반환하는 서비스
- **UI**: Streamlit 기반 "관제센터(control room)" 스타일 대시보드 — 좌측 제어반(입력
  폼) · 지도 · 판정 현황 패널 · LLM 질의응답 채팅의 4분할 구성

### 대표 기능

| 기능 | 요약 |
|---|---|
| 3종 높이 컴플라이언스 판정 | 일조권 사선제한(평문) / 국가유산 경관보호(평문) / 군사시설 고도제한(CKKS 암호문) |
| 실제 CKKS 동형암호 연산 | TenSEAL로 암호문−평문 뺄셈을 실제로 수행 (Mock이 아님, Phase 6에서 교체 완료) |
| 규정 테마 분리 판정 | 같은 시설(서울공항)도 군사기지법 제9조(제한보호구역)·제10조(비행안전구역)를 각각 독립 판정 |
| 반경 기반 범위 검색 | 시설 유형별 반경(군사기지법 제5조 근거)으로 인접 시설만 조회 |
| 격자 단위 지도 시각화 | 개별 시설 정밀 위치 대신 250m 격자 셀의 위험도(겹치는 시설 개수)만 표시 |
| LangGraph 오케스트레이션 | he_compute → authority_verify / plain_compute → rag_check → llm_summarize |
| 실제 tool-calling AI Agent | CLOVA Studio(HyperCLOVA X) function calling으로 판정 결과 설명·근거 조문 조회 |
| RAG 근거 인용 | ChromaDB에 색인한 법령 조문을 facility_id/regulation_theme으로 정확 조회 |
| Langfuse 트레이싱 | 노드별 실행을 allowlist 방식으로 redact 후 기록 |

## 2. 생성형 AI 핵심기술

### 사용 LLM 모델 스펙

- **제공자/모델**: 네이버클라우드 **CLOVA Studio(HyperCLOVA X)**, 기본 모델 `HCX-005`
  (`CLOVASTUDIO_MODEL` 환경변수로 교체 가능)
- **API**: Chat Completions v3 (`POST /v3/chat-completions/{model}`), 실제 **function
  calling(tool-calling)을 지원하는 API**를 그대로 사용 — OpenAI 호환 스키마
  (`{"name","description","parameters"}`)를 CLOVA Studio의 `{"type":"function","function":{...}}`
  포맷으로 변환해서 호출한다 (`src/graph/llm_client.py:call_llm_with_tools`)
- **호출 지점 2곳, 모듈 1개 공유**: `llm_summarize_node`(판정 결과 설명문, tool 없이 단발
  호출)와 `src/agent/router.py`의 채팅 핸들러(tool-calling 우선)가 `src/graph/llm_client.py`
  하나를 공유한다
- **키 미설정/장애 시**: 결정론적 템플릿·규칙 기반 답변으로 자동 폴백 — LLM 가용성이
  판정 결과 자체에 영향을 주지 않는다 (아래 "프롬프트 구조" 및 7번 데모 절 참고)

### 페르소나 템플릿 설계

ZeCret에는 사람처럼 대화하는 범용 페르소나가 아니라, **"이미 확정된 판정 결과를
설명만 하는 서기(書記)" 역할**로 의도적으로 좁힌 페르소나 두 개가 있다.

| 구분 | 시스템 프롬프트 핵심 | 위치 |
|---|---|---|
| 판정 요약 페르소나 | "판정은 이미 끝났다. 너는 아래 판정 결과를 설명하는 문장만 만들어라. 초과 여부를 스스로 재판단하거나 임의로 수치를 언급하지 마라. 근거는 아래 조문 발췌에서만 인용한다." | `src/graph/nodes.py::_LLM_SYSTEM_PROMPT` |
| 채팅 어시스턴트 페르소나 | "판정은 이미 끝났다 — 초과 여부를 스스로 재판단하지 마라. … 군사시설 항목은 기준 대비 수치가 항상 비공개로 표시된다 — 이 경우 구체적인 초과/부족량을 추측하거나 지어내지 말고 비공개라고 답하라. … 정확히 어떤 법령·조문을 위반했는지 묻는 질문에는 반드시 get_violation_citations 도구를 호출해 그 반환값에 있는 조문 원문만 인용하라." | `src/agent/router.py::_CHAT_SYSTEM_PROMPT` |

두 페르소나 모두 공통적으로 지키는 설계 원칙(=CLAUDE.md 절대 원칙 5)은 **"LLM은 판정
함수가 반환한 값에 근거해서만 자연어를 생성하고, 판정을 임의로 지어내지 않는다"**이다.
이건 프롬프트 문구뿐 아니라 함수 시그니처 수준에서도 강제된다 — 채팅 tool 목록
(`_TOOL_SPECS`)에는 판정을 재계산하는 `tool_check_height_compliance`를 **의도적으로
포함하지 않고**, 순수 조회 tool인 `get_violation_citations`만 노출한다.

### 최적화 프롬프트 구조

1. **입력 최소화(그라운딩 컨텍스트)** — `_build_grounding_context()`가 LLM에 넘기는
   정보를 "판정 결과(bool) + 기준 대비 여유/부족 수치(margin, 군사시설은 항상 비공개
   문구로 치환) + facility_id/regulation_theme + 근거 조문 요약"으로 고정한다.
   계획 높이 원본값, 정확한 좌표, 암호문은 프롬프트에 **아예 등장하지 않는다**.
2. **군사시설 vs 그 외 카테고리의 비대칭 처리** — margin이 `None`인 항목(군사시설)은
   프롬프트에서부터 "비공개"라는 문자열로 대체되어, LLM이 애초에 추측할 재료 자체를
   받지 못한다. 이건 "프롬프트에서 하지 말라고 지시"하는 방식보다 한 단계 더 강한
   차단(재료 자체를 안 줌)이다.
3. **3단계 폴백 구조** — (1) tool-calling 실제 호출 → (2) tool 없이 그라운딩 컨텍스트만
   채운 단발 `call_llm()` → (3) 질문 키워드 기반 규칙 답변(`_fallback_answer`). 이
   폴백은 프롬프트 엔지니어링과 맞닿아 있다 — 3단계 모두 **같은 grounding 데이터**를
   쓰기 때문에, 어느 단계로 떨어지든 "판정을 지어내지 않는다"는 성질이 유지된다.
4. **tool 재호출 강제** — 채팅 프롬프트는 "아래 컨텍스트에 요약된 근거 조문을 그대로
   베끼지 말고 도구 호출로 다시 확인하라"고 명시한다. 요약 컨텍스트만으로 답하면 LLM이
   문장을 재구성하며 미묘하게 왜곡할 수 있어, 정확한 인용이 필요한 질문에는 원문 재조회를
   강제하는 설계다.

## 3. 아키텍처 및 설계도

기존 `docs/architecture.md`(컴포넌트 다이어그램) / `docs/sequence.md`(시퀀스 다이어그램,
2종) / `docs/langgraph.md`(그래프 구조 — **손으로 그린 게 아니라 `graph.get_graph().draw_mermaid()`로
실제 컴파일된 그래프에서 추출**)가 코드와 정확히 일치하는 상태로 이미 관리되고 있어
그대로 재사용한다. 발표에서는 이 3개 문서를 순서대로 보여주면 된다.

### 데이터 파이프라인 흐름 (요약)

```
사용자 입력(X,Y,계획높이,이격거리)
    → find_nearby_restricted_zones (반경 검색, 평문 X/Y만 사용, Z 미등장)
    → run_full_compliance_check
        ├─ _PLAIN_SUBGRAPH × (일조권 1회 + 반경 내 국가유산 시설 수)
        │     plain_compute → rag_check → llm_summarize
        └─ _MILITARY_SUBGRAPH × (반경 내 군사시설 × 규정 테마 수)
              he_compute(CKKS 뺄셈) → authority_verify(HSM 자리, 부호만 복호화)
              → rag_check → llm_summarize
    → List[CategoryResult] (exceeds_limit, margin|None, final_message …)
    → app.py 렌더링 (배지 + 지도 격자 + 채팅)
```

핵심은 **두 서브그래프가 "search_zone_node 없이" 카테고리·테마 수만큼 반복 호출된다는
점**이다(`src/graph/runner.py`). 레퍼런스 그래프(`src/graph/build.py`, 시설 1건만 판정)는
`tests/test_graph_end_to_end.py` 전용으로 남아 있고, 실제 화면은 `runner.py` 경로를 쓴다 —
이 차이를 발표에서 헷갈리지 않도록 명확히 짚는 게 좋다.

### 배포 다이어그램

```
GitHub push(main)
  → GitHub Actions: test(pytest) → build(Docker 단일 이미지) → push(GHCR)
  → EC2_HOST 시크릿 있으면: SSH 접속 → docker pull → docker run
       (env-file: CLOVASTUDIO/VWORLD/LANGFUSE 키, volume: 관리기관 비밀키만 마운트)
```

- **단일 컨테이너**: `Dockerfile` 하나가 `app.py` + `src/` 전체(he/geo/agent/rag/compliance/db/graph)를
  패키징한다 — 도메인별 컨테이너 분리 없음(CLAUDE.md 배포 원칙)
- **비밀키 분리 배포**: `scripts/keys/`(관리기관 비밀키)는 `.dockerignore`로 이미지에서
  항상 제외되고, EC2에는 `scp`로 별도 배치 후 `docker run -v`로만 마운트한다 — 이미지
  자체는 비밀키를 담은 적이 없으므로 GHCR에 올라간 이미지가 노출돼도 비밀키는 안전
- **배포 대상**: EC2 단일 인스턴스(ECS 대비 관리형 인프라 부담이 이 규모엔 과함 — README
  참고)

### 정적 리소스·CDN 구성 (해당 없음 — 이유 포함)

목차상 "정적 리소스 CDN 구성도 확보"가 있으나, **ZeCret은 별도의 정적 리소스 CDN을
두지 않는다.** 이는 누락이 아니라 아키텍처 특성상 자연스러운 결과다:

- Streamlit은 서버 사이드 렌더링 앱이라 별도로 빌드된 JS/CSS 번들을 CDN에 올려 배포하는
  구조 자체가 없다(Streamlit 프레임워크가 자체 정적 자산을 서빙).
- 이 프로젝트에서 "정적 리소스에 가장 가까운 것"은 **VWorld WMTS 타일 서버**
  (`https://api.vworld.kr/req/wmts/...`)다 — 지도 배경 타일을 외부 공개 API에서 그때그때
  fetch하는 구조라, 우리가 CDN을 직접 운영할 필요가 없다.
- 암호문 캐시(`src/db/ciphertext_cache.db`, 725KB)와 공개 컨텍스트(`src/he/public_context.bin`,
  1.05MB)는 저장소에 커밋된 고정 산출물로 이미지에 함께 패키징되므로, 이 역시 별도
  CDN·오브젝트 스토리지가 필요 없는 규모다.

발표에서는 "왜 없는지"를 짧게 설명하고 넘어가는 편이, 없는 걸 억지로 만든 것처럼
보이는 것보다 낫다.

### ZeCret 자체의 오픈소스화 — 현재 상태와 부족한 부분

README.md 하단에 "License: MIT"라고 명시되어 있지만, **저장소 루트에 실제 `LICENSE`
파일이 존재하지 않는다.** 배지·문구만 있고 법적 효력을 가지는 라이선스 파일 자체가
없는 상태라, 오픈소스화를 발표에서 내세우려면 이 부분을 먼저 채워야 한다.

오픈소스로 공개하기에 유리한 점(이미 갖춰진 것):
- **비밀키·시크릿이 리포지토리에 없다** — `scripts/keys/`(관리기관 비밀키)는 `.gitignore`/`.dockerignore`
  양쪽에 모두 등록되어 있고, 커밋된 산출물(`ciphertext_cache.db`, `public_context.bin`)은
  전부 opaque bytes/공개키뿐이라 저장소를 그대로 공개해도 안전하다.
- **CI가 시크릿 없이도 항상 돈다** — `tests/conftest.py`가 Mock HE 아티팩트를 자동 준비하고
  LLM 키도 강제로 비워 결정론적 폴백 경로만 타므로, 외부 기여자가 포크해도 `pytest`가
  그대로 통과한다 — 오픈소스 기여 장벽이 낮다.
- **아키텍처 문서가 다이어그램 추출 방식** — `docs/langgraph.md`처럼 코드에서 직접 뽑은
  다이어그램은 코드가 바뀌어도 재생성만 하면 되므로 유지보수 부담이 적다.

부족한 점(발표 전 정리하면 좋은 것):

- `CONTRIBUTING.md` 등 기여 가이드 부재

  필요(다만 좌표 자체는 이미 공개된 항공정보간행물 기준이라 원칙적으로 문제는 없음)

## 5. 프로젝트 핵심 체크포인트 — Pain Point, 체크포인트 4개 실제 만족 여부, 정밀성 통계

### 5-1. 해결하려던 실무 핵심 포인트 (Pain Point)

> 군사시설 등 공개제한구역은 고도 등 정밀 높이제한 정보 공개가 규정상 제한된다.
> 민간 건축사업자는 그 정확한 기준을 모른 채로도 "내 건물이 위반인지 아닌지"를
> 사전에 확인해야 한다 — **안보상 비공개**와 **민간의 사전 확인 필요성**이 구조적으로
> 충돌한다. ZeCret은 높이제한 기준값(Z)을 암호화된 상태로 유지한 채 비교 연산을
> 수행하는 동형암호로 이 충돌을 해소하는 것을 핵심 목표로 잡았다.

### 5-2. 체크포인트 4개 — 실제 코드 기준 만족 여부 점검

아래는 기획 단계에서 받은 원문 체크포인트를 그대로 인용하고, **현재 코드가 이를
문자 그대로 만족하는지**를 코드 근거와 함께 점검한 결과다. "멘토님이 Z만 암호화하면
된다고 하신 것"과 "체크포인트 원문이 X,Y CSV 암호화를 요구하는 것처럼 읽히는 것" 사이의
간극도 여기서 함께 정리한다.

| # | 체크포인트 원문 | 실제 코드 상태 | 판정 |
|---|---|---|---|
| ① | CSV 업로드 시 민감 좌표 데이터(X, Y)가 CKKS 기반 동형암호로 안전하게 암호화되어 저장되는가? | CSV 업로드 기능 자체가 없다(값은 Streamlit 폼 직접 입력). X, Y는 어디서도 암호화되지 않는다 — CKKS로 암호화되는 건 군사시설 **높이제한 기준값(Z)** 뿐이고, 그마저도 "관리기관이 사전에 암호화해 캐시에 넣어둔 것"을 서비스가 조회만 하는 구조라 "CSV 업로드 시점의 암호화"라는 흐름 자체가 없다 (`scripts/generate_mock_ciphertexts.py`) | **문자 그대로는 불충족** — 아래 5-3에서 대안 논의 |
| ② | 복호화 없이 암호문 상태에서 범위 검색(BBOX 또는 원형 반경 검색)을 구현했는가? | 반경 검색(`find_nearby_restricted_zones`, `zone_radius_m`)은 실제로 원형 반경 검색이지만, **평문 X, Y 위에서** 수행된다(`haversine_m`). "암호문 상태에서" 검색하는 대상 자체가 없다 — 애초에 좌표가 암호화되어 있지 않기 때문 | **원문 그대로는 불충족**(암호문 위 검색 아님) — 다만 반경 검색 기능 자체는 실제로 잘 동작함 |
| ③ | 보안 수준에 맞춰 좌표 노출을 차단하면서도 지도 위에 정보를 표현하는 대안 설계(격자/마스킹/서버 렌더링 등)를 적용했는가? | `src/geo/risk_grid.py`가 250m 격자 셀 단위로 "겹치는 인접 시설 개수"만 표시하고, 개별 국가유산·군사시설의 정확한 위치는 지도에 마커로 그리지 않는다(`app.py`). 계획 건물 본인 위치만 정확히 표시(사용자 자신의 입력이라 비노출 대상이 아님) | **충족** |
| ④ | 클라이언트에 평문이나 암호문 대신 토큰/인덱스 참조값(예: DEC:datasetId:index)만을 전달하여 보안성을 극대화했는가? | `src/tokens.py::issue_token`이 발급하는 `HE:{facility_id}:{regulation_theme}` 토큰을 실제 반환 경로(`src/db/ciphertext_cache.py::describe_ciphertext_for_display`)에 연결했다. `app.py`의 "🔬 이 항목의 참조 토큰 확인" 패널은 더 이상 ciphertext_blob의 hex 프리뷰나 바이트 길이를 노출하지 않고 참조 토큰만 반환한다. `facility_id`/`facility_name` 원문은 여전히 그대로 노출되지만, 이는 원칙 2가 막으려는 대상(Z값·암호문)과 무관한 공개 정보(원칙 3, 실재 시설 위치·명칭)라 별도 조치가 필요 없다고 판단 | **충족** (연결 완료) |

**한 줄 요약**: ①②는 "체크포인트가 상정한 일반적 시나리오(CSV로 좌표를 올리고, 그
좌표 자체가 암호문 상태로 검색된다)"와 ZeCret이 실제로 채택한 시나리오(좌표는 원래
공개 정보, 비공개 대상은 높이뿐)가 서로 다른 전제를 깔고 있어서 생기는 불일치다.
③은 실제로 잘 구현되어 있다. ④는 전제와 무관한 **순수 구현 공백**이었으나, 참조
토큰을 실제 반환 경로에 연결하고 암호문 hex 노출 패널을 제거해 해결했다(부록의
재현 커맨드 참고).

### 5-3. "CSV 업로드 + X,Y 암호화"를 추가해야 하는가 — 검토 및 권장

멘토님 의견("Z만 암호화하면 된다")과 CLAUDE.md 원칙 3("X, Y는 평문으로 취급해도
된다")은 **이 도메인의 실제 위협 모델을 정확히 반영한 결정**이다. 근거:

- 계획 건물의 X, Y는 **사용자 본인이 입력하는 자기 정보**다 — 애초에 사용자가 이미
  알고 있는 값이라 "비공개 대상"이 될 수 없다.
- 군사시설(서울공항)의 X, Y는 항공정보간행물(AIP)에 **이미 공개된 기준점(ARP) 수준
  근사치**다 — 안보상 비공개는 좌표가 아니라 **고도제한 수치**다(`src/compliance/config.py`
  주석 참고). 국가유산(남한산성)도 마찬가지로 이미 공개된 지리 정보다.
- 즉 이 서비스의 실제 위협 모델에는 **"암호화해야 할 민감 X,Y" 자체가 존재하지 않는다.**
  체크포인트 원문은 "민감 좌표 데이터"라는 일반적 표현을 쓰고 있지만, ZeCret의 도메인
  에서는 그 전제가 성립하지 않는다.

**권장 방향**: 없는 위협을 있는 것처럼 꾸며서 X,Y CSV 암호화 파이프라인을 새로 만드는
것은 추천하지 않는다. 실제로 암호화할 필요가 없는 값을 암호화하는 코드는 "체크포인트
문구를 흉내 낸 겉치레"로 보일 위험이 있고, CLAUDE.md 원칙 3과도 정면으로 충돌한다.
대신 발표에서는:

1. **왜 X,Y가 아니라 Z만 암호화 대상인지를 도메인 근거(AIP 공개 기준점 vs 안보상
   비공개 고도)로 명시적으로 설명**하고, 체크포인트 ①②를 "이 프로젝트의 위협 모델에
   맞게 스코프를 재정의했다"는 의사결정으로 정직하게 프레이밍한다(멘토 협의 사실도
   근거로 언급).
2. ④(토큰 참조값)는 도메인 재정의와 무관한 **순수 구현 공백**이었으므로 실제로
   고쳤다 — `facility_id`/`facility_name`을 그대로 반환하는 대신 `tokens.py`의
   `issue_token()`을 `describe_ciphertext_for_display()`에 실제로 붙였고, "🔬 실제
   암호문 확인" 패널은 이제 hex 프리뷰를 노출하지 않고 참조 토큰만 보여주는 "🔬 이
   항목의 참조 토큰 확인" 패널로 교체했다.

이 결정 자체(Z만 암호화 대상으로 스코프를 재정의한 것)는 발표에서 근거를 들어
설명해야 하는 사안이고, ④번 수정은 이미 반영을 완료했다 — 남은 잔여 위험(반복
질의로 Z를 역산하는 오라클 공격)은 아래 5-4절에서 별도로 다룬다.

### 5-4. 반복 질의 오라클 방어 — Z값 역산 가능성과 그 대응

체크포인트 ①②를 "좌표 대신 Z만 암호화"로 재정의한 이상, Z만 암호화해도 판정
결과(위반/적합 bool)를 몇 번이고 물어볼 수 있다면 그 자체가 새로운 정보 유출
경로가 된다는 잔여 위험이 남는다. 상세 분석과 설계 근거는
[`docs/oracle_defense.md`](oracle_defense.md)에 정리했고, 핵심만 요약한다.

**문제 정의 — 비교 결과 1비트 오라클**: `authority_verify_node`는 매 요청마다 diff
암호문의 부호를 복호화해 정확한 bool 하나(`exceeds_limit`)를 돌려준다. Z값 자체는
어디에도 평문으로 나가지 않지만, 클라이언트가 `plan_height`를 바꿔가며 이 bool을
반복 관찰하면 **이진탐색으로 Z를 원하는 정밀도까지 역산**할 수 있다 — 탐색 구간이
0~200m라면 1m까지 좁히는 데 약 8회, 1cm까지 약 15회 질의면 충분하다. 이는 CKKS나
TenSEAL의 결함이 아니라, "비교 결과 1비트만 반환하는 오라클"이 어떤 스킴을 쓰든
질의 인터페이스 자체에서 새는 정보(threshold oracle leakage)라 근본적으로 없앨 수
없다는 점이 핵심이다.

**참고한 연구**: Dinur–Nissim database reconstruction theorem(2003, 노이즈를 섞은
통계 질의도 충분히 반복하면 원본을 복원할 수 있음을 증명)과 Sparse Vector
Technique(Dwork & Roth, 임계값 반복 질의에 대응하는 차분 프라이버시 기법 — 예산
소진 시 응답을 끊는 구조)가 "질의에 노이즈를 섞거나, 질의 횟수에 예산을 걸고
소진 시 거부한다"는 결론으로 수렴한다.

**왜 노이즈 삽입이 아니라 하드 캡을 택했는가**: 판정 결과는 "이 건물이 법을
위반하는가"라는 법적 판단이고, CLAUDE.md 절대 원칙 1은 이 판정을 임의로 지어내지
않을 것을 요구한다. 확률적으로 틀린 답을 섞는 SVT 표준 구현은 이 원칙과 정면으로
충돌하므로, 대신 **틀린 답 대신 판정 자체를 거부**하는 하드 질의예산을 택했다.

**구현** (`src/security/query_budget.py`):
- `(facility_id, regulation_theme)` 조합별 누적 질의 횟수를 추적(신원 미구분 —
  보호 대상이 "이 시설의 비공개 Z값"이지 "누가 물었는지"가 아니기 때문)
- 기본 예산은 `HE_QUERY_BUDGET_PER_REGULATION` 환경변수(기본값 50)
- `authority_verify_node`가 `verify_diff()` 호출 직전에 `consume_query_budget()`을
  호출, 예산 초과 시 `QueryBudgetExceededError`를 던져 `exceeds_limit`을 만들어내지
  않음
- `app.py`는 이 예외를 사이드바 에러로 표시하고 이전 검색 결과는 화면에 유지
- `tests/test_query_budget.py`가 예산 초과 거부·시설/테마별 독립 추적·판정 미조작을
  검증

**모니터링**: Langfuse `authority_verify` span에 정상 판정 시 `query_count`(누적
질의 순번)를, 예산 초과 거부 시 `level=ERROR` + `query_count`/`query_budget`을
싣는다 — 대시보드에서 `name=authority_verify` + `level=ERROR`로 필터링하면 정상
조회와 오라클 probing 의심 이벤트를 바로 구분할 수 있다.

**알려진 잔여 한계**: 신원 미구분(여러 계정/세션으로 예산 나눠쓰기 우회 가능),
인메모리 카운터(프로세스 재시작 시 초기화), `compute_he_batch_demo()`가
`verify_diff_vector()`를 직접 호출해 이 예산을 우회, `run_full_compliance_check()`가
화면 소요시간 표시를 위해 규정 테마당 실제 판정과 별개로 한 번 더 호출해 검색
1회가 예산을 2회씩 소진시킴(기본값 50은 이 배수를 감안한 값). 궁극적으로 예산
소진 시 거부만으로는 "여러 계정으로 나눠 질의"를 막지 못하며, 완전한 안전판은
암호학이 아니라 신원 확인·재문의 비용 같은 행정적 마찰과 결합될 때 완성된다.

### 5-5. 상세 정밀성 검정 통계

**CKKS 정밀도(노이즈) 튜닝**

| 파라미터 단계 | poly_modulus_degree | global_scale | 직렬화→역직렬화→뺄셈→복호화 노이즈 | 경계값(예: 45.0==45.0) 부호 안정성 |
|---|---|---|---|---|
| 1차 시도 | 4096 | 2^21 | 최대 ±0.002m(수 mm) | 불안정 — 부호 역전 재현됨 |
| 최종(현재) | 8192 | 2^40 | 약 1e-9m(무시 가능) | 안정 — 20회 반복 검증 |

- galois/relinearization 키를 생성하지 않아(뺄셈 1회만 필요) 공개 컨텍스트 크기를
  줄임 — **실측**: `src/he/public_context.bin` = **1,098,546 bytes(약 1.05MB)**.
  (galois key 포함 시 약 18MB라는 수치는 `docs/presentation_script.md`에 기록된
  기존 문서 기준 수치이며, 이번 점검에서 별도로 재측정하지는 않았다.)

### Edge Case / 예외 상황 실시간 처리 데모 포인트

발표 목차의 "Edge Case 및 예외 상황에 대한 실시간 예외 처리(특히 Z값을 예측하려는
비정상 행동 감지)" 요구에 맞춰, 아래 항목들은 실제로 화면에서 즉석으로 재현 가능한
예외 처리다. 그중 가장 핵심은 아래 오라클 probing 시나리오다.

> **★ 핵심 데모 — Z값 역산 시도(오라클 probing) 실시간 차단**
>
> **시나리오**: 같은 좌표(127.1567, 37.4504)에서 군사시설
> (`military_seongnam_airport`/`protect_zone`) 판정을 계획 높이만 바꿔가며(예:
> 30m→40m→44m→46m…) 이진탐색 방식으로 `HE_QUERY_BUDGET_PER_REGULATION`(기본
> 50)회를 초과해 반복 검색한다 — 실제 공격자가 비공개 고도제한값을 좁혀 나가려는
> 행동을 그대로 재현한다.
>
> **예상 동작**: 51번째 질의부터 `authority_verify_node`가
> `consume_query_budget()`에서 `QueryBudgetExceededError`를 던지고, `app.py`가
> 이를 잡아 사이드바에 "'military_seongnam_airport'/'protect_zone' 조합에 대한
> 조회 한도(50회)를 초과했습니다…" 에러 메시지를 표시한다 — 화면의 이전 판정
> 결과는 그대로 남아 있고, `exceeds_limit`은 절대 임의로 만들어지지 않는다.
>
> **Langfuse로 즉시 확인**: 같은 순간 Langfuse 대시보드에서
> `name=authority_verify` + `level=ERROR`로 필터링하면, 방금 발생한 span이
> `query_count=51`, `query_budget=50` 필드와 함께 즉시 나타난다 — "정상적인 단발
> 조회"와 "임계값 이상 반복 probing"이 대시보드에서 실시간으로 구분됨을 그대로
> 보여줄 수 있다.
>
> **말할 내용 제안**: "지금처럼 높이를 바꿔가며 반복적으로 물어보면, 이론적으로는
> 이진탐색으로 비공개 기준값을 좁혀나갈 수 있습니다. 저희는 이걸 응답에 노이즈를
> 섞는 방식(차분 프라이버시 SVT) 대신, 예산을 다 쓰면 판정 자체를 거부하는
> 하드캡으로 막았습니다 — 법적 판정을 확률적으로 틀리게 답하는 건 저희 원칙에
> 어긋나기 때문입니다. 그리고 이 시도는 Langfuse에 ERROR 레벨 이벤트로 그대로
> 남아서, 나중에 이 패턴만 걸러서 감사할 수 있습니다."

1. **CKKS 경계값(부호 불안정) 케이스**: 계획높이를 기준값과 정확히 같은 값으로
   넣었을 때 어떤 일이 일어나는지 설명하며, 이를 의도적으로 테스트에서 제외한 이유
   (근사 연산의 본질적 한계, 사용자가 비공개 기준값을 정확히 맞힐 가능성 없음)를
   함께 짚으면 "한계를 숨기지 않고 분석했다"는 인상을 준다.
2. **LLM API 키 제거 → 결정론적 폴백**: `.env`에서 `CLOVASTUDIO_API_KEY`를 비우고
   재검색하면 `llm_summarize_node`가 템플릿 문구로, 채팅은 규칙 기반 답변
   (`_fallback_answer`)으로 즉시 전환된다 — 판정 결과(exceeds_limit) 자체는 전혀
   바뀌지 않는다는 것을 실시간으로 보여줄 수 있다.
3. **VWorld 지도 API 키 제거 → 배경지도 폴백**: `VWORLD_API_KEY`가 없으면 실제 건물
   배경 없이 `dark_no_labels` 스타일로 자동 전환 — 판정 기능 자체에는 영향이 없음을
   보여준다.
4. **암호문 캐시 미준비 상태**: `python scripts/generate_mock_ciphertexts.py`를 아직
   실행하지 않은 상태에서 앱을 켜면 `config.py`의 `_load_military_regulation()`이
   즉시 `RuntimeError`로 실패한다 — "조용히 평문 기본값으로 대체하지 않고 명시적으로
   실패시킨다"는 원칙 1 강제 사례로 보여줄 수 있다(단, 시연 중 실수로 이 상태가
   되지 않도록 사전 점검 필요).
5. **군사시설 판정에서 참조 토큰 확인**: "🔬 이 항목의 참조 토큰 확인" 패널을 열어
   `HE:{facility_id}:{regulation_theme}` 형식의 참조 토큰만 표시되는 것을 보여준다 —
   이전에는 ciphertext_blob의 hex 프리뷰를 그대로 노출했으나(체크포인트④ 미해결
   지점), 이번 갱신에서 참조 토큰 연결로 수정해 원본 값도 암호문 자체도 화면에
   등장하지 않는다는 것을 실시간으로 짚어줄 수 있다.
6. **`pytest tests/test_information_exposure.py -v`를 터미널에서 라이브로 실행**:
   군사시설 항목의 margin이 항상 None인지 자동 검증되는 과정을 시연 중 직접
   보여주는 것도 좋은 방법(`docs/demo_scenario.md`에도 이미 언급됨).

| SIMD 배치 데모의 질의예산 우회 | `compute_he_batch_demo()`가 `verify_diff_vector()`를 직접 호출해 예산을 거치지 않음 — 배치 경로에도 동일 예산 체크를 적용하거나, 공식 판정 경로로 승격 전까지 우회 가능성을 문서에 명시 |
| 군사시설 1개 시설만 HE 적용 | 실제 다른 군사시설/공역으로 확장, 실 고시 고도제한 수치 연동(현재는 placeholder) |
| 일조권 이격거리 수동 입력 | GIS 지적경계 폴리곤 기반 자동 산출(CLAUDE.md에 이미 "이후 별도 과제"로 명시) |
| `route_query`/`handle_rag_query` 미구현 | 일반 법령 질의 라우팅 구현 (`src/agent/router.py`에 `NotImplementedError`로 남아 있음) |

| `LICENSE` 파일 부재 | 오픈소스화를 실제로 진행하려면 README의 MIT 표기에 맞는 라이선스 파일 추가 |
